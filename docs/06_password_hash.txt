# Password Hashing (Step 4 - Auth System)

We added password hashing to convert the plain password into
a secure, unreadable version before saving it.

File: controllers/AuthController.php

Why hash passwords?
- If a hacker steals the database, they see all passwords
- Plain text: "123456" → hacker can read it immediately
- Hashed: "$2y$10$xKz8r..." → hacker cannot reverse it
- Hashing protects users even if the database is compromised

---

NEW FUNCTION: password_hash()

What is it?
A built-in PHP function that converts a password into a secure hash.

How to use it:
$hashedPassword = password_hash($password, PASSWORD_DEFAULT);

Parameters:
- $password         → the original password (e.g. "123456")
- PASSWORD_DEFAULT  → tells PHP to use the best algorithm available
                      Currently it uses bcrypt
                      If PHP adds a better one later, it switches automatically

What it returns:
A long string like: $2y$10$xKz8rL9QmNvB...
This string contains:
- $2y$     → the algorithm used (bcrypt)
- 10$      → the "cost" (how many times it scrambles)
- The rest → the salt + the hash

---

Key concepts:

1. One-way function
   You can convert "123456" → hash
   But you CANNOT convert hash → "123456"
   There is no reverse function
   This is what makes it secure

2. Salt (random data)
   password_hash() adds random data (called a salt) each time
   This means the same password produces DIFFERENT hashes:
   "123456" → $2y$10$abc...
   "123456" → $2y$10$xyz...  (different!)
   This prevents "rainbow table" attacks

3. How to check passwords later?
   When a user logs in, we use password_verify():
   password_verify("123456", $hashedFromDB)
   Returns true if they match, false if not
   We will use this in the LOGIN system

---

Flow so far:
User submits form → POST data received → validation passes
→ password is hashed → (next: save to database)

Security rules:
- NEVER store plain text passwords in the database
- NEVER display passwords to users (we showed it for testing only)
- ALWAYS use password_hash() for storing
- ALWAYS use password_verify() for checking (login)
