# Database Port Fallback & Multi-Environment Troubleshooting

This document explains the automatic database port fallback configuration implemented in the TQSEET system. It describes how the connection adapter handles port variations across different local machines (such as home and school environments) while ensuring security in a live production environment.

---

## 1. The Problem

When working on multiple development machines (e.g., a school laptop vs. a home laptop):
* **School Laptop**: MySQL is configured to run on port `3307` to avoid local system conflicts.
* **Home Laptop**: MySQL runs on the default port `3306` inside a standard XAMPP environment.

If the port is hardcoded in the repository (e.g., `3307`), cloning the project to a home laptop fails with a connection error:
`DB ERROR: No connection could be made because the target machine actively refused it`.

Manually switching the port back and forth before committing files is error-prone and disrupts the development flow.

---

## 2. The Solution: Dynamic localhost Fallback

Instead of maintaining separate branches or changing code on every environment switch, the database connection wrapper in `config/db.php` has been upgraded to automatically detect port availability on development hosts.

1. **Attempt 3306**: It first tries to connect to the standard MySQL port (`3306`).
2. **Fallback to 3307**: If the first attempt fails and the hostname corresponds to a local instance (`localhost` or `127.0.0.1`), it immediately tries the fallback port (`3307`).
3. **Production Guard**: If the database host is a remote production server, the system fails fast and logs the error immediately, bypassing the fallback mechanism to maintain strict security.

---

## 3. Implementation Details

The database adapter in `config/db.php` was modified as follows:

```php
public function connect() {

    // ✅ Enable exceptions for precise error catching
    mysqli_report(MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT);

    // Try primary port 3306 first (standard XAMPP / local installations)
    try {
        return new mysqli($this->host, $this->user, $this->password, $this->dbname, 3306);
    } catch (mysqli_sql_exception $e) {
        
        // If host is localhost/127.0.0.1, try the school laptop fallback port (3307)
        if ($this->host === "localhost" || $this->host === "127.0.0.1") {
            try {
                return new mysqli($this->host, $this->user, $this->password, $this->dbname, 3307);
            } catch (mysqli_sql_exception $fallbackException) {
                // Log and show user error if both fail
                logError("DB ERROR (both 3306/3307 failed): " . $fallbackException->getMessage());
                die(userError("db_error"));
            }
        } else {
            // In production/hosting environments, fail immediately without attempting fallback
            logError("DB ERROR: " . $e->getMessage());
            die(userError("db_error"));
        }
    }
}
```

---

## 4. Verification

* **Home Laptop (Port 3306)**: Successfully connects on the first try. Connection overhead is 0ms.
* **School Laptop (Port 3307)**: Fails instantly on 3306 (error code caught immediately) and falls back to 3307. Total fallback delay is sub-millisecond.
* **Production Hosting**: Works seamlessly on whatever port is configured, failing safely if the DB is unreachable.
